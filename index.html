Delete Account API

How a user deletes their account, what happens during the 30-day recovery period, and exactly what is erased afterwards.

Base URL: https://api.routinix.app/api/v1  ·  Body format: JSON

The idea in one minute

Deleting an account is not instant. It happens in two stages so a mistake can be undone.

Day 0: user taps Delete The account is switched off at once and everyone is signed out. Nothing is erased yet.
Days 1 to 30: recovery window The user can change their mind and restore the account. All data is still there.
After day 30: erased A daily job erases the personal data. This cannot be undone.

1. Request deletion

POST/users/me/delete/

Needs the user's access token: Authorization: Bearer <access token>.

Request body

FieldRequiredNotes
confirmationyesMust be exactly the text DELETE. Show the user a box where they type it.
current_passwordone of the twoThe user's password (accounts created with email and password).
google_id_tokenone of the twoA fresh Google ID token, for accounts that sign in with Google and have no password.
{
  "current_password": "Str0ng!Passw0rd",
  "confirmation": "DELETE"
}

Success response 202 Accepted

{
  "id": "5c790b01-b89d-4c7b-bcbc-880a53b92070",
  "status": "PENDING",
  "requested_at": "2026-11-25T08:47:26.777773Z",
  "scheduled_for": "2026-12-25T08:47:26.777773Z"
}

scheduled_for is the deadline. It is exactly 30 days after requested_at. Until that moment the user can still recover the account. Show it as a date, for example "Your account will be deleted on 25 Dec 2026."

Errors

StatusWhen
400 VALIDATION_ERRORconfirmation is not DELETE, no password or token was sent, or the password is wrong (the error names the field).
400The account is not active, for example it is already pending deletion.
401The access token is missing or expired. Refresh it and try again.

What happens right away

  • The account is disabled: the user cannot sign in.
  • Every session is signed out on every device.
  • Any pending password-reset or email-verification codes are cancelled.
  • The user's Motivation posts disappear from the feed, because the author is disabled.
  • No data is deleted yet. Everything is kept untouched for the 30 days.

After the 202, the app should clear its stored tokens and cached data and return to the sign-in screen.

Tip: offer POST /users/me/export/ (a copy of the user's data) before deletion, so they can keep a copy.

2. The 30-day recovery period

During these 30 days the account is "pending deletion". The user cannot use the app, but nothing is lost. If they sign in the normal way it fails, and the app should offer "Recover my account" instead.

How it behaves

What the user triesWhat they get
Sign in with email and password401 "Invalid email or password." (the account is switched off)
Sign in with Google409 ACCOUNT_PENDING_DELETION. Show the recover option.
Register again with the same email409 ACCOUNT_PENDING_DELETION. The user can recover, or start a new account on purpose (see below).
Recover the accountWorks until scheduled_for, then never again.

Recover the account

POST/users/recover-deletion/

Public: no token needed, because the user is signed out. Limited to 10 attempts per hour.

FieldRequiredNotes
email + passwordone optionThe account's email and its password.
google_id_tokenother optionA fresh Google ID token, for Google accounts.
{
  "email": "user@example.com",
  "password": "Str0ng!Passw0rd"
}

Success response 204 No Content

The body is empty. The account is active again with all its data. The user is not signed in automatically: the app must now sign them in normally with POST /auth/login/ (or Google).

Errors

StatusWhen
401 AUTHENTICATION_FAILED"Unable to recover this account." Wrong email or password, the account is not pending deletion, or the 30 days have already passed. The message is deliberately the same for all of these.
503 GOOGLE_UNAVAILABLEGoogle verification is temporarily unavailable. Try again later.
429Too many attempts. Wait and try again.

Starting a brand-new account instead

If the user wants a fresh start with the same email, call POST /auth/register/ again with "start_new_account": true and "previous_password" set to the old account's password. The old account is then erased immediately and a new one is created. Without the old password this is refused, so nobody else can wipe the account by typing its email.

3. What is deleted after 30 days

A job runs once a day at 02:30 UTC. Any account whose scheduled_for has passed is erased then. So deletion happens at the first daily run after day 30, not at the exact minute.

Erased

  • Profile: name, date of birth, avatar, bio
  • Email address (replaced by an anonymous placeholder)
  • Password and all sign-in sessions
  • Linked Google sign-in
  • Routines, schedules, completions and categories
  • Points, balance, history and rewards (including redemptions)
  • Streak and daily points history
  • Motivation posts, likes, bookmarks, follows, reports and pings
  • Registered devices, push tokens and diagnostics
  • Blocking settings, unlock history and trusted contact
  • Screen-time and activity data
  • Notification settings and history
  • Trial and premium grants
  • Referral links (the user's code is switched off)

Kept

  • An anonymous empty account record: no name, no real email, no password, it can never sign in.
  • App-store subscription identifiers, so financial records stay intact and a purchase cannot be reused on another account.
  • Support tickets and security logs, only for their normal retention period. The security log stores scrambled (hashed) identifiers, not raw emails.

After deletion, recovery is impossible. The same email address can be used to register a new account.

Important for the app: deleting the account does not cancel an App Store or Google Play subscription. Tell the user to cancel it in the store, or they will keep being billed.
